About PHISHSHIELD

PHISHSHIELD is a phishing website detection system designed to help users avoid fake and harmful websites that attempt to steal sensitive information.

Phishing websites often imitate legitimate platforms to capture passwords, banking credentials, and personal data by exploiting user trust.

Small changes in URLs frequently go unnoticed, which makes manual detection unreliable. This system identifies such threats before user interaction occurs.

There are three main files

Model Training File (Phishingproject.ipynb)

This notebook is responsible for training and testing the phishing detection model by handling data loading, analysis, model training, and evaluation.

Imported Libraries and Their Purpose

NumPy

NumPy handles numerical data efficiently by storing feature values in arrays. Since machine learning models operate on numerical inputs, NumPy enables fast and reliable mathematical operations.

Pandas

Pandas is used for data handling and preprocessing by loading CSV files into structured tables, cleaning data, and selecting relevant features for analysis.

Warnings

Warnings may appear during model training but do not affect the results. These warnings are suppressed to keep the notebook output clean and readable.

Train-Test Split

The dataset is divided into training and testing sets to prevent memorization. 80% of the data is used for training, while 20% is reserved for testing unseen URLs.

Model Selection

Why Gradient Boosting Was Chosen

Phishing patterns are complex and non-linear, making simple rule-based approaches ineffective. Gradient Boosting combines multiple decision trees where each tree corrects previous errors, producing a strong and adaptive model.

Decision Tree

A single decision tree tends to overfit by memorizing training data, resulting in poor performance on new URLs and unreliable predictions.

Random Forest

Random Forest relies on many independent trees, increasing memory usage and training time while lacking the corrective learning behavior of boosting methods.

Logistic Regression

Logistic Regression assumes linear relationships between features, which does not match the deceptive and complex nature of phishing URLs.

Why Gradient Boosting Fits Best

Gradient Boosting learns incrementally, handles non-linear patterns well, delivers strong results with fewer trees, and balances accuracy with computational efficiency.

Gradient Boosting Classifier

The Gradient Boosting classifier builds decision trees sequentially, allowing each tree to improve upon the previous model’s mistakes.

Learning Rate

The learning rate controls how quickly the model adapts to errors, requiring careful tuning to balance stability and performance.

Max Depth

Max depth determines tree complexity, where deeper trees capture more detail but risk overfitting, while shallow trees may miss important patterns.

Grid Search

Grid search evaluates multiple parameter combinations using cross-validation to select the model with the best F1 score and avoid biased results.

Model Evaluation Metrics

Accuracy

Accuracy measures overall correctness but can be misleading when dealing with imbalanced phishing datasets.

Recall

Recall measures how many phishing websites are successfully detected, making it a critical metric for user safety.

Precision

Precision evaluates the trustworthiness of phishing predictions by measuring how many flagged sites are actually malicious.

F1 Score

The F1 score balances precision and recall and performs well on imbalanced datasets.

Storing the Model

The trained model is stored using Pickle, allowing reuse without retraining and saving computational resources.

Final Prediction Test

A sample phishing URL is tested to verify end-to-end functionality, where predictions classify URLs as safe or phishing.

Conclusion

This project demonstrates how machine learning can effectively detect phishing websites, with Gradient Boosting providing strong performance and scope for future real-time enhancements.

Feature Extraction Module (feature.py)

This module converts a website URL into numerical features. Machine learning models cannot understand text directly. They require structured numeric input.

This file analyzes the URL structure and webpage behavior. It then generates security-based features for prediction.

Libraries Used and Why They Are Required

ipaddress

Used to check whether the website uses a raw IP address. Phishing sites often hide behind IP addresses instead of domains.

re (Regular Expressions)

Used to detect suspicious patterns in URLs. It helps identify symbols, shortened links, hidden email forms, and other phishing tricks.

socket

Used to obtain the actual IP address of a domain. This helps verify whether the domain is linked to suspicious servers.

requests

Used to fetch webpage content. Without downloading the page, HTML-based security checks are not possible.

BeautifulSoup

Used to parse HTML content. It allows inspection of forms, links, scripts, images, and embedded elements.

urlparse

Used to break the URL into components such as domain name and protocol. This helps analyze structure and detect anomalies.

How the Feature Extraction Works

When a user submits a URL, the system first analyzes its structure. It checks domain patterns, protocol type, length, and suspicious symbols.

It then inspects the webpage content for risky behavior. This includes external resource loading, suspicious form actions, popups, redirects, and iframe usage.

Each security check produces a numerical value. These values collectively form the feature vector.

Why This Module Is Important

The machine learning model cannot evaluate raw URLs. It depends entirely on structured features.

This module acts as the intelligence bridge between user input and model prediction.

Application Controller – app.py

This file runs the full web system. It connects the website interface with the machine learning model.

It takes a URL from the user, sends it to the model, and shows the final result.

Libraries Used and Why They Are Needed

Flask

Flask creates the web application. It handles user requests and page responses.

When a user clicks “Scan URL”, Flask receives that request.

NumPy

NumPy converts extracted features into arrays. The machine learning model only accepts numeric arrays.

Pickle

Pickle loads the trained model from a saved file. This avoids training the model every time the app runs.

Warnings

Warning messages are hidden. This keeps the server output clean.

FeatureExtraction

This module analyzes the URL. It converts the website into 30 numeric features.

Convert Module

This module converts model output into readable messages like “Safe” or “Phishing”.

Session

Session temporarily stores the scan result. It prevents duplicate submissions on refresh.

How the System Works Step by Step

Step 1: The user enters a URL.

Step 2: The scan route receives the URL.

Step 3: FeatureExtraction generates 30 features.

Step 4: The trained model predicts the result.

Step 5: The result is converted into readable form.

Step 6: The result is shown on the main page.

Why This File Is Important

This file connects everything together.

Without it, the model cannot talk to users.

It controls the full prediction flow.
